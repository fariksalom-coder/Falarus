# Диктант — FalaRus

## Архитектура

Игра использует существующие React/TypeScript, Router, AuthContext, GameGate, UI-кнопки, Express, middleware пользователя/администратора, PostgreSQL pool и статическую раздачу `uploads`. Новые подключения к БД, auth, user state и отдельный storage не создавались.

`/games/dictation` — темы. `/games/dictation/:topicId` — игра. `/secure-admin-a9k7x4p2/dictation` — существующая админка (с учётом настроенного admin base).

Четыре таблицы из задания плюс `dictation_sessions`: снимок заданий и состояние игрового раунда. Снимки нужны для воспроизводимой проверки после редактирования контента и повторной отправки ответа. До ответа клиент получает только id/type/difficulty/audio_url, без текста и перевода. Проверка, combo, жизни, очки и прогресс считаются сервером. Повтор одного ответа идемпотентен; чужие сессии недоступны. Сессия восстанавливается после обновления вкладки.

Прогресс темы — число уникальных пройденных активных заданий с аудио. `correct_items`/`wrong_items` отражают последний ответ на каждое задание. `best_score` и `best_combo` — максимумы игровых сессий, включая досрочно законченные. Прогресс сохраняется после каждого ответа, поэтому закрытие игры его не стирает. Очки этой игры не добавляются повторно в общий рейтинг платформы.

Ошибочные задания имеют повышенный вес без дублирования внутри раунда. При правильном ответе задание выходит из очереди ошибок. Кнопка «Повторить ошибки» выбирает нерешённые ошибки текущей темы. Ответ не исправляется автоматически: регистр и повторные пробелы игнорируются, у предложения допускается отсутствие одной финальной точки. Ё/е, формы слов и прочая пунктуация различаются. `mistake_count` — расстояние Левенштейна после нормализации; приоритет повторения учитывает количество ошибочных попыток, а не число буквенных опечаток.

## Миграция, контент, импорт

Миграция: `db/migrations/187_dictation.sql`. В существующей среде с настроенным DATABASE_URL применить только её:

```sh
node scripts/dev/applyMigrations.mjs --only 187
```

Для production предпочтительно выполнить этот SQL штатным PostgreSQL-клиентом; не запускайте все ещё не применённые миграции других задач только ради «Диктанта».

```sh
npm run seed:dictation -- --validate
npm run seed:dictation
```

Источник: `content/dictation/dictation_content.json`: 20 тем × (25 слов + 25 предложений) = 1000 заданий. Все русские фразы и узбекские переводы находятся в контент-файле, не во frontend. Seed работает транзакционно, повторный запуск не перезаписывает изменения администратора. ID задания стабилен: ключ темы + номер строки. Не меняйте порядок уже импортированных строк; редактируйте их через админку. Для другого файла: `--file=path/to/content.json`.

## Подготовка аудио

```sh
npm run audio:dictation
npm run audio:dictation -- --topic=work
npm run audio:dictation -- --limit=10
```

TTS вызывается только этим административным скриптом, не игровым API. Он переиспользует `server/services/tts.service.ts`: русская речь, естественная скорость 1.0, профиль `sozlar`, существующий OpenAI voice/model и кеш. Один MP3 на задание, без вступлений. Существующий непустой файл пропускается. Новый MP3 проверяется ffprobe, записывается атомарно, затем URL записывается в БД. При ошибке скрипт останавливается, готовые файлы остаются; повторный запуск продолжает подготовку.

Хранилище: `uploads/dictation/<item-id>/generated-<text-hash>.mp3`. Публичный URL: `/uploads/dictation/...`. Загруженные администратором замены имеют UUID-имена, чтобы не нарушать уже начатые сессии. Изменение русского текста обнуляет audio_url до подготовки/загрузки нового аудио. Задания без аудио не попадают в игру. Генератор не переозвучивает существующие аудио, включая ручные замены.

Для крупной подготовки разрешены три отдельные очереди `--shard=0`, `--shard=1`, `--shard=2`. Они делят тексты по устойчивому хешу; одинаковые тексты попадают в одну очередь и переиспользуют кеш. Advisory locks исключают одновременно запущенную обычную генерацию и повтор одного shard. Утилиты требуют ffprobe и настроенные ключи существующего TTS, ни один ключ не передаётся в браузер.

## Добавление контента

- **Тема:** в админке «Создать тему», заполнить ID, RU/UZ название и описание, значок, фон, порядок и активность; сохранить.
- **Задание:** выбрать тему, заполнить слово/предложение, перевод, сложность 1–5 и порядок; сохранить; загрузить MP3 или запустить подготовку аудио.
- **Аудио:** MP3 до 5 МБ и 60 секунд; в админке доступны загрузка, замена и прослушивание.
- **Фон:** добавить значение и сцену в `src/components/dictation/GameBackground.tsx` и CSS, затем вариант выбора в админке. Фон получает только background_id, не данные задания.
- **Формула очков:** `dictationPoints` в `shared/dictation.ts`: слово 10, предложение 15, плюс 2 за каждый следующий combo-шаг, бонус ограничен 20 очками.

## API

Пользователь, существующий Bearer token:

- `GET /api/games/dictation/topics`
- `POST /api/games/dictation/sessions` — topic_id, count (10/20/50), review, request_id UUID.
- `GET /api/games/dictation/sessions/:id`
- `POST /api/games/dictation/sessions/:id/answer` — position, answer.

Администратор, существующий admin token:

- `GET/POST /api/admin/dictation/topics`
- `GET /api/admin/dictation/items?topic=<id>` — включает статистику ответов/ошибок.
- `POST /api/admin/dictation/items` — создать/изменить.
- `POST /api/admin/dictation/items/:id/audio` — multipart audio.
