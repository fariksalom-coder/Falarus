# Последовательный доступ к урокам и заданиям

## Порог успеха

- **≥ 70%** правильных ответов в задании → задание считается **пройденным**, открывается **следующее** задание.
- **&lt; 70%** → задание можно **пересдать**; следующее задание **не открывается**.

## Уроки

- **Урок 1** всегда открыт первым (после учёта подписки / freemium).
- **Следующий урок** открывается, когда **все** задания текущего урока пройдены с ≥ 70%.

## Данные

- Локально: `localStorage` (`lessonTaskResults`).
- Сервер: таблица `lesson_task_results` (синхронизация через `saveLessonTaskResult` / загрузка через `fetchLessonTaskResults`).
- Контекст `SequentialLessonProvider` объединяет локальные и серверные результаты.

## Код

| Файл | Назначение |
|------|------------|
| `src/lib/sequentialLessonProgress.ts` | Чистая логика: разблокировка урока/задания, завершение урока |
| `src/lib/lessonUrlTaskMapping.ts` | URL → номер задания (в т.ч. особый случай `/lesson-11`) |
| `src/context/SequentialLessonContext.tsx` | Состояние и API `isLessonAccessible` / `isTaskAccessible` |
| `src/components/SequentialAccessEnforcer.tsx` | Редирект при прямом заходе на закрытый маршрут |
| `src/hooks/useLessonsSubscriptionLock.ts` | Блокировка по тарифу (как на дашборде) |

## UI

- **Dashboard**: карточки с учётом подписки + последовательности; галочка при завершении урока.
- Кнопки заданий на страницах уроков по-прежнему ведут на маршруты; **недоступные** URL перехватываются `SequentialAccessEnforcer`.

## Доработка страниц уроков

Чтобы кнопка не вела на заблокированное задание без «мигания» редиректа, на странице можно вызвать `useSequentialLesson().isTaskAccessible(lessonPath, taskNumber)` и отключать кнопку.

## Повторение 182-дневного курса после окончания премиума

После окончания подписки можно повторять полностью завершённые дни русского курса. Если завершены дни 1–90, они остаются доступны, а незавершённый день 91 требует продления. Для каждого дня отдельно хранится серверный признак `user_kunlik_day_progress.review_unlocked`. Он устанавливается после завершения всех пяти блоков при действующем премиуме; повторные попытки его не сбрасывают. Позднейшее добавление заданий в день тоже не отменяет сохранённое право повторения.

API `/api/user/access` возвращает `kunlik_review_days` отдельно от `subscription_active`. Карта, карточки заданий, прямые ссылки, содержание дня и серверные тесты используют единое правило доступа. Повторение не открывает остальные платные функции и не позволяет завершить новый день без подписки. Административная заморозка блокирует повторение платных дней; заморозка за задолженность продолжает обрабатываться существующим middleware. Для устных упражнений без активного премиума принимаются задания из конкретного доступного дня; недельное повторение исключает недоступные дни.

Перед запуском новой версии примените `db/migrations/202_kunlik_completed_day_review.sql`. Миграция восстанавливает право повторения по существующему завершённому прогрессу при наличии истории русского премиума (профиль, подписка или одобренный платёж). Нулевой пробный день, незавершённые дни, золотые аккаунты и аккаунты без такой истории не получают новых прав через миграцию. Её повторное применение безопасно. Она не изменяет срок подписки и результаты заданий.

Проверки: сценарий 90/182 после окончания трёхмесячного премиума, отказ для дня 91 через API, отсутствие новых прав при подмене PATCH, сохранение результатов при повторении, восстановление разных источников премиума, заморозка, продление и повторная фиксация завершённого дня, изменение содержания и истечение подписки при прогретом кэше. Тесты находятся в `tests/kunlikReviewAccess.test.ts` и `tests/kunlikDayAccess.test.ts`.
