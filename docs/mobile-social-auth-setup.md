# Mobile Social Sign-In — Google + Apple

Setup guide for the **Google** and **Apple** sign-in flows in the Flutter
mobile app (`mobile/`). The backend code is in `server.ts` →
`/api/auth/google` and `/api/auth/apple`, backed by
`server/services/socialAuth.service.ts`.

> Apple is iOS-only by product decision. The button is hidden on Android by
> a `Platform.isIOS` guard in `login_screen.dart` / `register_screen.dart`.

---

## 1. Database

Run migration **`120_oauth_identities.sql`**:

```
psql "$SUPABASE_DB_URL" -f supabase/migrations/120_oauth_identities.sql
# or via the helper:
npm run db:push
```

What it does:

- Makes `users.password` nullable (social users have no password).
- Adds `user_oauth_identities (user_id, provider, provider_user_id, …)`
  with a unique index on `(provider, provider_user_id)`.

## 2. Google Cloud Console

URL: <https://console.cloud.google.com> → **APIs & Services → Credentials**.

Create three OAuth 2.0 Client IDs in the same Google Cloud project:

| Application type | Required fields | Used for |
|---|---|---|
| **iOS** | Bundle ID = your iOS app bundle (e.g. `uz.falarus.app`) | The Google iOS plugin |
| **Android** | Package name = `uz.falarus.app`; SHA-1 of **both** debug and release keystores | The Google Android plugin |
| **Web application** | (no redirect URIs needed for native flow) | `serverClientId` in Flutter + backend audience check |

### Getting Android SHA-1

```bash
# Debug keystore (auto-generated by Android Studio)
keytool -list -v -keystore ~/.android/debug.keystore \
  -alias androiddebugkey -storepass android -keypass android | grep SHA1

# Release keystore (your production .jks)
keytool -list -v -keystore /path/to/release.jks -alias YOUR_ALIAS | grep SHA1
```

Add **both** SHA-1 fingerprints to the **Android** OAuth client.

### Download iOS plist

After creating the iOS client → **Download plist** → save as
`mobile/ios/Runner/GoogleService-Info.plist`. Open it, copy the
`REVERSED_CLIENT_ID` value, and replace `REPLACE_WITH_REVERSED_CLIENT_ID`
inside `mobile/ios/Runner/Info.plist` → `CFBundleURLSchemes`.

> The `GoogleService-Info.plist` should **not** be committed if you treat
> client IDs as sensitive; add it to `.gitignore`. Otherwise it's safe to
> commit — these IDs are public anyway.

## 3. Apple Developer Portal

URL: <https://developer.apple.com> → **Certificates, Identifiers & Profiles**.

### Enable Sign in with Apple on the App ID

1. **Identifiers** → select your App ID (e.g. `uz.falarus.app`).
2. Tick **Sign in with Apple** under capabilities → **Save**.
3. No further config needed — Apple validates with your Bundle ID
   automatically for native iOS flows.

### Add the capability in Xcode

1. Open `mobile/ios/Runner.xcworkspace` in Xcode.
2. Select the **Runner** target → **Signing & Capabilities** tab.
3. Click **+ Capability** → **Sign in with Apple**.
4. Xcode wires `mobile/ios/Runner/Runner.entitlements` (already in repo)
   into the project. Verify the capability shows under the target.

## 4. Backend environment variables

Add to your production `.env` (and any dev `.env.local`):

```bash
# Comma-separated audiences accepted from Apple identity_token (Bundle IDs).
APPLE_BUNDLE_ID="uz.falarus.app"

# Each Google OAuth client your app uses — the backend whitelists their aud claim.

GOOGLE_OAUTH_ANDROID_CLIENT_ID="123-bbb.apps.googleusercontent.com"
GOOGLE_OAUTH_WEB_CLIENT_ID="123-ccc.apps.googleusercontent.com"
```

`.env.example` already documents these.

## 5. Flutter build-time variables

The mobile app reads Google client IDs from `--dart-define` so they don't
land in source. Values live in **`mobile/dart_defines.json`** (gitignored;
template is `mobile/dart_defines.example.json`).

Current values (FalaRus production):

```json
{
  "GOOGLE_SERVER_CLIENT_ID": "76774374355-nipao16d92mfk24kfk5nd11lrji7i07c.apps.googleusercontent.com",
  "GOOGLE_IOS_CLIENT_ID":    "76774374355-apjnm0r9s2cafbmu7ecfftnj64rm1paf.apps.googleusercontent.com"
}
```

Run / build commands:

```bash
# Dev
cd mobile
flutter run --dart-define-from-file=dart_defines.json

# Release builds
flutter build ios --release --dart-define-from-file=dart_defines.json
flutter build apk --release --dart-define-from-file=dart_defines.json
# (GOOGLE_IOS_CLIENT_ID is ignored on Android.)
```

`GOOGLE_SERVER_CLIENT_ID` must equal the **Web** client ID in step 2.
That's the audience the backend whitelists when verifying `id_token`.

## 6. End-to-end flow (what happens at runtime)

```
┌─ Mobile (Flutter) ────────┐    ┌─ Backend (Express) ─────────┐
│  user taps Google button  │    │                             │
│  ─ google_sign_in plugin  │    │                             │
│    → idToken              │───▶│ POST /api/auth/google       │
│                           │    │  verifies via Google JWKS   │
│                           │    │  (audience ∈ whitelist)     │
│                           │    │  find or create user        │
│                           │    │  insert user_oauth_identity │
│                           │◀───│  { token, user, isNewUser } │
│  store JWT in secure_store│    │                             │
│  if isNewUser → onboarding│    │                             │
└───────────────────────────┘    └─────────────────────────────┘
```

Apple is identical except the client uses `sign_in_with_apple`,
`identity_token` + a SHA-256-hashed `nonce`, and the backend verifies
against `https://appleid.apple.com/auth/keys`.

After all of the above is wired:

- [ ] Run the migration on the target database.
- [ ] iOS simulator: `flutter run --dart-define=...` → tap "Google bilan
      davom etish" → Google sheet appears → choose account → returns to
      app → token stored, user lands on `/onboarding` (new) or main
      tabs (existing).
- [ ] iOS device: tap "Apple bilan davom etish" → Face ID sheet → returns
      to app → same behavior.
- [ ] Android emulator: same Google flow. Apple button must be hidden.
- [ ] Tap Google, dismiss the sheet → no error banner, just returns.
- [ ] Re-tap Google with the same account → logs in without onboarding.

## 8. Common pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| `Google id_token kerak` (400) | Plugin returned `null` idToken | Ensure `serverClientId` is set in `SocialAuthService` (Web client ID, not iOS/Android) |
| `Google identifikatsiyasi tasdiqlanmadi` (401) | Token `aud` not in backend whitelist | Add the right Client ID to `GOOGLE_OAUTH_*_CLIENT_ID` envs and restart server |
| Apple flow opens but returns `notHandled` | App ID missing "Sign in with Apple" capability | Re-enable in developer.apple.com and re-provision |
| Android crashes opening Google sheet | SHA-1 not registered for the keystore actually signing the APK | Add release keystore SHA-1 to the Android OAuth client |
| URL scheme redirect fails on iOS | `REPLACE_WITH_REVERSED_CLIENT_ID` still in `Info.plist` | Replace with REVERSED_CLIENT_ID from `GoogleService-Info.plist` |
| **`Ошибка 401: invalid_client` / `no registered origin`** (web) | Browser origin not in Google Cloud **Authorized JavaScript origins** | See §9 below — mobile Google does **not** need this; web does |

## 9. Web site — Google Sign-In (`/login`, `/register`)

The Flutter app uses native plugins (no JavaScript origins). The **website** uses
[Google Identity Services](https://developers.google.com/identity/gsi/web) in the
browser — Google checks the page origin (`http://localhost:3001`, `https://falarus.uz`, …).

### Fix `no registered origin`

1. Open [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials).
2. Select project **76774374355** (FalaRus).
3. Open the **Web application** OAuth client:
   `76774374355-nipao16d92mfk24kfk5nd11lrji7i07c.apps.googleusercontent.com`
   (same as `GOOGLE_SERVER_CLIENT_ID` / mobile `serverClientId`).
4. Under **Authorized JavaScript origins**, add every URL you use:

   ```
   http://localhost:3000
   http://localhost:3001
   https://falarus.uz
   https://www.falarus.uz
   ```

5. Under **Authorized redirect URIs**, add the web callback (GIS redirect mode):

   ```
   http://localhost:3000/api/auth/google/credential
   http://localhost:3001/api/auth/google/credential
   https://falarus.uz/api/auth/google/credential
   https://www.falarus.uz/api/auth/google/credential
   ```

6. Save. Wait 1–5 minutes, then hard-refresh the login page.

> **Note:** If you test on `localhost:3001` but only `falarus.uz` is registered,
> production works and local dev shows `invalid_client` — that is expected until
> localhost is added.
